# Принос

Сайтът се поддържа от учениците в клуба. Най-честата промяна е нова среща и
тя е един Markdown файл — не се пипа нито шаблон, нито CSS.

Правилата за поведение са в [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).

## Локален старт

Нужен е [Bun](https://bun.sh). Версията е в `.bun-version` — същата, която
ползва и CI.

```bash
bun install
bun run dev        # http://localhost:4321
bun run check      # Biome: lint и формат
bun run format     # Biome: поправя форматирането
bun run typecheck  # astro check: типове и frontmatter срещу схемите
bun run build      # статичен изход в dist/
```

Еднократно, за да ти подава git темплейта за комити:

```bash
git config commit.template .gitmessage
```

Конвенцията е описана в коментарите на самия [`.gitmessage`](.gitmessage).
`git config` е локален за твоя clone, затова стъпката е ръчна.

## Как се добавя среща

Нов файл в `src/content/meetings/`, после pull request.

**Името на файла е публичен адрес.** От него се прави котвата на срещата
(`/meetings#pilot-docker-deep-dive`), затова:

- тематичен slug с малки латински букви и тирета — `docker-basics.md`
- **не** дата и **не** точки: `15.10.2026.md` би дало `/meetings#15.10.2026`
- веднъж качено, името не се сменя — чупи всеки споделен линк

```yaml
---
date: 2026-10-15
time: 16:10–17:30        # по избор
title: Заглавие на лекцията
speaker: Име Фамилия
room: "8.3.1"            # по избор
status: planned          # planned | past
materials: https://...   # по избор, за минали срещи
image: ../../assets/meetings/docker-basics.jpg   # по избор, кадър 16:9
imageCaption: Подпис към кадъра                  # по избор
---

По избор: един до три абзаца обикновен текст.
```

Кадърът се слага в `src/assets/meetings/`, **не** в `public/`. Оттам минава
през `image()` на Astro, който го оптимизира и проверява, че съществува —
грешен път чупи `bun run build` вместо да даде празно място на сайта.
Съотношението е 16:9; друго се изрязва.

Ако `bun run typecheck` се оплаче за frontmatter, грешката е в полетата:
схемите са в `src/content.config.ts` и съобщенията са на български.

## Какво се очаква в PR

Чеклистът е в шаблона на pull request-а. Накратко: `check`, `typecheck` и
`build` минават, промяната е гледана на 375 px ширина, и не добавя заявка
към чужд домейн (N1 — шрифтовете и иконките са в репото).

## Сигурност

Сайтът е статичен: няма сървър, няма база и няма потребителски данни. Ако
намериш нещо, което все пак изглежда като проблем със сигурността, пиши на
`devops-club@elsys-bg.org` вместо да отваряш публичен issue.
